# Running the System

From the model to two boards executing a scan plan.

---

## Where developer code lives

HAMR generates the infrastructure: the node, the ports, the dispatch, the AADL run-time
services. Application behaviour is written against the generated component API and is the
only hand-written code in the system.

| Component | Generated | Hand-written |
| --- | --- | --- |
| `ScanController` | `hamr/ros2` — node, ports, dispatch, plan scaffolding | the scan plans |
| `StepperController` | `hamr/ros2` → `firmware/SeedImagingStepperNode` — node, ports, dispatch | `firmware/SeedImagingStepper/` — stepping, GPIO, pin map in `board.cpp` |

`board.cpp` holds the pin table. It is hand-written and is the one place where the model's
axis names meet physical pins, which is why
[Platform.md](Platform.md#wiring) treats the board-to-axis assignment as something to be
established empirically rather than assumed.

Nothing inside `firmware/SeedImagingStepperNode` should be edited. It is regenerated by
`bin/hamr.sh` and any change there is lost on the next run.

## 1. Type check the model

In CodeIVE, open the project and run **SysMLv2 Type Check**. This is the authoritative
check on the model itself.

Equivalent on the command line, as step 1 of the full run:

```
export SIREUM_HOME=$HOME/Applications/Sireum-4.20260810/Sireum
cd SeedImaging_SysMLv2
bin/verify.sh
```

Expected: `Well-formed!`

## 2. Generate

```
bin/hamr.sh
```

Runs both HAMR invocations recorded at the top of the model, exports the model constants
to C/C++, and syncs the generated micro-ROS library into `firmware/`.

| Output | Contents |
| --- | --- |
| `hamr/ros2` | ROS 2 (rclcpp, C++) package and the micro-ROS (rclc, C) sources |
| `hamr/slang` | Slang reference implementation, Logika contracts, GUMBOX harnesses |
| `firmware/SeedImagingStepperNode` | the micro-ROS library, copied for the Arduino build |

Regeneration is idempotent. After a run with no model change, both of these produce no
output:

```
diff -r -x out -x Makefile <backup>/hamr hamr
diff -r <backup>/firmware firmware
```

`Makefile` and `out` are excluded for a reason, not convenience: `hamr/ros2/Makefile` is
rewritten by `bin/hamr.sh` itself on every run, and `hamr/slang/out` is the Scala build
directory created when the test suite compiles. Neither is generated model output.

## 3. Flash the ESP32

Copy the generated library into the Arduino libraries folder:

```
cp -R firmware/SeedImagingStepperNode ~/Documents/Arduino/libraries/
```

Then add an `esp32s3` folder alongside the shipped `esp32` one:

```
cp -R ~/Documents/Arduino/libraries/micro_ros_arduino/src/esp32 \
      ~/Documents/Arduino/libraries/micro_ros_arduino/src/esp32s3
```

**This step is required and its omission is confusing.** `micro_ros_arduino` ships
precompiled archives under a directory named for the chip family. The Arduino Nano ESP32
is an ESP32-S3, and with no `esp32s3` directory the sketch compiles cleanly and then fails
at link with a wall of undefined references to the micro-ROS symbols.

Restart the Arduino IDE so it rescans libraries. Open
`firmware/SeedImagingStepper/SeedImagingStepper.ino`, select
**Arduino ESP32 Boards → Arduino Nano ESP32**, and upload.

---

## 4. Build on the Jetson

Copy the project across, then:

```
cd hamr/ros2
colcon build --packages-skip seed_imaging_microros_pkg
source install/setup.bash
```

`seed_imaging_microros_pkg` is the ESP32 half. It is skipped because it targets the MCU
and does not build under the host toolchain.

---

## 5. Start the agent

One agent only. Check first:

```
sudo docker ps
```

Then:

```
sudo docker run -it --rm -v /dev:/dev --privileged --net=host \
  microros/micro-ros-agent:humble serial --dev /dev/ttyACM0 -v4
```

Leave it running. Press reset on the ESP32 and watch for `create_participant`,
`create_publisher` and `create_subscriber` lines — the client only attempts to connect at
boot, so a board that was already running when the agent started will not appear until it
is reset.

---

## 6. Start the ROS 2 node

New terminal:

```
source /opt/ros/humble/setup.bash
source <path>/hamr/ros2/install/setup.bash
ros2 launch seed_imaging_cpp_pkg_bringup SeedImagingSystem_Instance_ros2.launch.py
```

Confirm both nodes are present:

```
ros2 node list     # expect /esp32_stepper and /jetson_scan
ros2 topic list    # expect /scan/start and /stepper/{z,x,y}/{cmd,pos}
```

A duplicate-name warning here means more than one agent is running.

---

## 7. Run a plan

Level the tilt by hand and reset the ESP32 first, so the axes are at the home position
[`SI-MCU-1`](../sysmlv2/SeedImaging.sysml#L230) assumes.

```
ros2 topic pub --once /scan/start std_msgs/msg/Int32 "{data: 1}"   # axis self-test
ros2 topic pub --once /scan/start std_msgs/msg/Int32 "{data: 2}"   # imaging scan
```

The launch terminal logs each move as the plan executes.

---

## Commanding an axis directly

Useful for checking a contract. Commands are **relative steps**:

```
ros2 topic pub --once /stepper/x/cmd std_msgs/msg/Int32 "{data: 25}"    # +45 deg
ros2 topic pub --once /stepper/x/cmd std_msgs/msg/Int32 "{data: -50}"   # sweep to -45 deg
ros2 topic pub --once /stepper/x/cmd std_msgs/msg/Int32 "{data: -1}"    # refused at the limit
```

The third produces no motion and the tilt holds at −45°. That is
[`SI-MCU-9`](../sysmlv2/SeedImaging.sysml#L277) executing in firmware. Watch the position:

```
ros2 topic echo /stepper/x/pos
```

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `Package 'seed_imaging_cpp_pkg_bringup' not found` | Workspace not sourced in this terminal |
| Link errors naming micro-ROS symbols | The `esp32s3` copy in step 3 was skipped |
| `SeedImagingStepperNode.h: No such file` | Library not copied, or the IDE not restarted after copying |
| Agent alternates `running` / `server stopped` once per second | Two agents are running; `sudo docker ps` and stop one |
| `Serial port not found`, `/dev/ttyACM0` absent | Board not enumerating. Try a different cable and port; if `dmesg` shows repeated `error -110`, reboot the Jetson to reset the USB controller |
| Commands publish, nothing moves | 12 V not connected, or the command is outside the axis range and is being refused |
| `Waiting for at least 1 matching subscription` | The ESP32 node is not connected |
