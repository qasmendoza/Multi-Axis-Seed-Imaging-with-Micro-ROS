# Components

For each component: what it is for, what language it is implemented in, and what its
contracts are there to establish.

---

## Implementation languages at a glance

One model, three generated implementations. Two are deployed; one exists to be verified.

| Component | Deployed implementation | Verified implementation |
| --- | --- | --- |
| `ScanController` | **ROS 2 / rclcpp, C++** — generated by `--platform ros2` into `hamr/ros2` | **Slang** — generated by `--platform JVM` into `hamr/slang` |
| `StepperController` | **micro-ROS / rclc, C** — generated into `hamr/ros2`, copied into `firmware/SeedImagingStepperNode` | **Slang** |

Logika proves properties of the Slang. The hardware runs the C and C++. What bridges
those is step 7 of `bin/verify.sh`, and its limits are stated honestly in
[Noteworthy.md](Noteworthy.md#the-slangcpp-verification-gap).

Developer application code — the actual stepping, the GPIO writes — sits behind the HAMR
component API in `firmware/SeedImagingStepper/`. See [Running.md](Running.md).

## StepperController

[`part def StepperController :> Thread`](../sysmlv2/SeedImaging.sysml#L181) ·
micro-ROS node `esp32_stepper` · implemented in **C**

### Purpose

Owns the physical axes. It is the only component that touches a motor. It receives a
relative step command on one of three axes, decides whether the move is permissible,
performs it if so, and acknowledges with the resulting absolute position.

The decision to **refuse** rather than clamp is deliberate: an out-of-range command
leaves the axis where it is and the current position is still published, so the host
always learns the true state.

### Properties

| Property | Value | Why |
| --- | --- | --- |
| `Dispatch_Protocol` | `Sporadic` | It reacts to commands; there is no periodic work |
| `Compute_Execution_Time` | `0 [ms] .. 2080 [ms]` | Worst case is a maximal move: 400 steps × 5 ms + 80 ms settle |
| `Ros_Node_Kind` | `microRos` | Selects the micro-ROS back-end for this thread |

The execution-time bound is derived from model constants rather than measured, which
makes it checkable against `MAX_MOVE_STEPS`, `STEP_INTERVAL_MS` and `SETTLE_MS`.

### GUMBO state

```
zPosition : Integer_32    // turntable, steps in [0, 200)
xPosition : Integer_32    // tilt, steps from level, in [-25, 25]
yPosition : Integer_32    // reserved rotary axis, steps in [0, 200)
```

### What the contracts are for

**Physical safety.** [`SI-MCU-2`](../sysmlv2/SeedImaging.sysml#L244) and
[`SI-MCU-9`](../sysmlv2/SeedImaging.sysml#L277) exist because the tilt bracket occludes
the camera past ±45°. The limit is physical; the contract makes it enforceable and
provable rather than a convention in the firmware.

**Representation invariants.** [`SI-MCU-3`](../sysmlv2/SeedImaging.sysml#L247) keeps the
rotary axes modulo one revolution, so a position is always a valid index and arithmetic
cannot drift out of range over a long scan.

**Axis isolation.** [`SI-MCU-6`](../sysmlv2/SeedImaging.sysml#L263),
[`SI-MCU-10`](../sysmlv2/SeedImaging.sysml#L281) and
[`SI-MCU-14`](../sysmlv2/SeedImaging.sysml#L299) each state that a command on one axis
leaves the other two untouched. Pin-mapping errors are the expected failure mode in this
class of system, and these are the clauses that would catch one.

**Acknowledgement discipline.** [`SI-MCU-7`](../sysmlv2/SeedImaging.sysml#L266),
[`SI-MCU-11`](../sysmlv2/SeedImaging.sysml#L284) and
[`SI-MCU-15`](../sysmlv2/SeedImaging.sysml#L302) require exactly one acknowledgement, on
the matching port only. The host's plan sequencing depends on this.

**Initialisation.** [`SI-MCU-1`](../sysmlv2/SeedImaging.sysml#L230) states that all three
axes are taken to be at home at power-up. This is an assumption about the deployment, not
a sensed fact — there are no homing switches. It is why the operating procedure requires
levelling the tilt by hand before reset.

## ScanController

[`part def ScanController :> Thread`](../sysmlv2/SeedImaging.sysml#L317) ·
ROS 2 node `jetson_scan` · implemented in **C++ (rclcpp)**

### Purpose

Owns the scan plan. It issues exactly one move, waits for that specific acknowledgement,
then advances. It never has two moves outstanding, and it halts permanently rather than
issue a move it cannot show to be safe.

### Properties

| Property | Value | Why |
| --- | --- | --- |
| `Dispatch_Protocol` | `Sporadic` | Driven by operator requests and acknowledgements |
| `Ros_Node_Kind` | `ros2` | Selects the rclcpp back-end |

### GUMBO state

```
pending      : Boolean      // a move was sent and is not yet acknowledged
awaitAxis    : Integer_32   // axis of the move in flight: 0 = Z, 1 = X, 2 = Y
tiltEstimate : Integer_32   // last tilt position reported by the ESP32
planIndex    : Integer_32   // index of the next move
planEnd      : Integer_32   // end of the plan, exclusive
halted       : Boolean      // stopped for good: a move would be unsafe
```

Local functions: [`cmdSent`](../sysmlv2/SeedImaging.sysml#L350) and
[`isAxis`](../sysmlv2/SeedImaging.sysml#L353).

### What the contracts are for

**Protocol discipline.** [`SI-HOST-2`](../sysmlv2/SeedImaging.sysml#L379) and
[`SI-HOST-3`](../sysmlv2/SeedImaging.sysml#L383) enforce one command per dispatch and one
move in flight. Without these, the plan could run ahead of the hardware and
acknowledgements would no longer identify which move completed.

**Correlation.** [`SI-HOST-6`](../sysmlv2/SeedImaging.sysml#L395) ties the move in flight
to the axis commanded, and
[`SI-HOST-13`](../sysmlv2/SeedImaging.sysml#L439),
[`SI-HOST-15`](../sysmlv2/SeedImaging.sysml#L457) and
[`SI-HOST-17`](../sysmlv2/SeedImaging.sysml#L475) state that an acknowledgement which is
not the awaited one changes nothing. A stray or duplicated message cannot advance the
plan.

**Safety before commanding.** [`SI-HOST-4`](../sysmlv2/SeedImaging.sysml#L392) requires a
tilt command to be bounded and to land within ±45° *before* it is issued. The host does
not rely on the MCU refusing it. The property is enforced on both sides.

**Fail-stop.** [`SI-HOST-8`](../sysmlv2/SeedImaging.sysml#L405) makes halting permanent.
A system that cannot prove its next move safe stops rather than continues.

**Bounded state.** [`SI-HOST-7`](../sysmlv2/SeedImaging.sysml#L400) and
[`SI-HOST-10`](../sysmlv2/SeedImaging.sysml#L412) keep the awaited axis, plan position and
tilt estimate in range, which is what allows the proofs to close without unbounded
reasoning about plan length.

## Why the tilt limit appears on both sides

`SI-HOST-4` has the host refuse to issue an unsafe tilt command. `SI-MCU-9` has the MCU
refuse to act on one. Both reference the same library predicate,
[`isSafeTiltMove`](../sysmlv2/SeedImaging.sysml#L91).

This is not redundancy for its own sake. The host's check depends on `tiltEstimate`, which
is its belief about the axis. The MCU's check uses `xPosition`, which is the axis. The
integration constraint on `xPos` is what connects the two, and it is the subject of
[Integration-Constraints.md](Integration-Constraints.md).
